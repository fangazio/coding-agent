# Coding Agent

**简体中文** | [English](./README.en.md)

一份可复用的 AI 编程协作规范，帮助 coding agent 像对交付负责的软件工程师一样工作：理解需求、控制修改范围、完成实现、验证结果，并清楚说明尚未解决的问题。

核心文件是 [AGENTS.md](./AGENTS.md)。它定义工作原则与执行边界，不包含独立运行的程序，也不绑定特定编程语言或技术栈。

## 设计目标

在保证正确性和可维护性的前提下，减少重复探索、无效工具调用和不必要的流程。任务是否成功完成，比步骤数量、文档长度或工具调用次数更重要。

- **交付最小完整方案**：实现用户要求的行为，避免顺手清理、无关重构和过度设计。
- **按风险投入精力**：局部小改动直接处理；共享接口、认证、并发和数据迁移需要更充分的分析与验证。
- **用证据驱动行动**：获得足够上下文后开始实现，只有出现新风险或验证失败时才扩大探索。
- **保护已有工作**：保留用户的未提交修改，遵守授权范围，不擅自执行破坏性操作或提交、推送代码。
- **如实报告结果**：区分验证通过、验证失败和验证受阻，不把未验证的行为描述为成功。

## 如何使用

1. 下载本仓库的 [AGENTS.md](./AGENTS.md)。
2. 将文件放到目标项目中你所用编程助手约定的指令位置；如果助手支持项目根目录的 `AGENTS.md`，可以放在项目根目录。
3. 如果项目已有指令文件，先比较并合并适用规则，保留项目原有约束，不要直接覆盖。
4. 根据项目实际情况补充必要信息，再让助手执行具体任务。

不同助手的文件发现方式、指令优先级和目录作用域可能不同，请按实际运行环境接入；仅将文件上传到 GitHub，不会自动配置其他项目中的助手。

## 建议补充的项目信息

在 `AGENTS.md` 的第 12 节，或项目已有的专门文档中，记录经过验证、经常需要用到的事实：

| 信息 | 应记录的内容 |
| --- | --- |
| 代码入口 | 主要源码目录、共享模块和架构边界 |
| 开发环境 | 包管理器、必要的运行时与启动方式 |
| 验证方式 | 真实可用的测试、构建、类型检查与 lint 命令 |
| 特殊约束 | 生成文件的来源、迁移规则、兼容性要求 |
| 工具与文档 | 已配置的代码图工具优先级、权威文档入口 |

只加入会影响日常决策的信息。较长或低频的流程应放到独立文档中，并从指令文件引用。

## 规范覆盖范围

| 章节 | 关注点 |
| --- | --- |
| 1–3：目标、授权与任务规模 | 明确交付标准，按不确定性和影响范围选择工作深度 |
| 4–5：上下文与工具 | 有针对性地获取信息，复用仍有效的证据，减少重复查询 |
| 6：任务委派 | 仅在允许且有独立任务价值时使用子代理，主代理负责整合与核验 |
| 7–8：工程实践与任务重点 | 复用既有结构，保持类型安全，分别处理构建、调试、重构、评审和 UI 工作 |
| 9：安全、数据与 Git | 保护凭据和用户工作，遵守修改与发布授权 |
| 10–11：验证与交付 | 执行适用检查，准确报告完成状态和阻塞原因 |
| 12：项目事实与维护 | 保持指令简洁、可验证，依据实际使用结果改进 |

## 工作方式

规范鼓励助手遵循以下工作节奏，而不是为每个任务强制增加同一套流程：

1. 明确用户期望、修改范围和成功标准。
2. 获取足以行动的代码、依赖和项目约束。
3. 完成授权范围内的最小完整实现。
4. 执行能够发现相关问题的验证，并检查最终变更。
5. 交付结果，说明验证证据及剩余限制。

遇到阻塞时，先完成不依赖阻塞项的工作，再明确说明缺失的输入、权限或环境条件。

## 能力边界

这份文件提供行为指导，不能替代运行环境的权限控制、测试或代码审查，也不会自动安装代码图、文档查询等工具。模型选择、工具可用性、缓存、计费和最终执行效果由所使用的助手及运行环境决定。

本仓库不承诺固定的 token 节省比例或性能提升。评估修改时，应先比较正确性与完成度，再结合相同模型、仓库条件下的耗时、重复查询及实际用量数据判断效果。
